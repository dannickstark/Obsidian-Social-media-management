# M6 — OAuth, major-platform adapters and image generation

## Goal

Extend Social Planner from the M5 automatic-posting wave to the major platform APIs and a shared image-generation workflow, while preserving the plugin-only deployment model, per-device secret storage, approval rules, retry safety, and assisted fallbacks.

## Scope and delivery order

M6 is delivered as independently testable slices:

1. Desktop OAuth feasibility spike and shared login helper.
2. Facebook Pages, including hand-over to Facebook native scheduling.
3. Instagram Business accounts, after settling image hosting.
4. X publishing and media/thread handling.
5. LinkedIn personal profiles, then company pages when the required product access exists.
6. OpenAI image generation, composer window, focal-point crops, and Claude tool.
7. Token-health reminders.
8. Platform setup guides and Obsidian community-plugin submission.
9. Whole-milestone review, fixes, smoke checklist, and merge.

Each slice must leave the existing assisted flow working and must not require a hosted companion server.

## Design decisions

### OAuth

The first slice is a spike answering whether a desktop-only OAuth flow can complete securely without a companion server. The probe uses a loopback callback on `127.0.0.1`, PKCE, a random state value, and Obsidian's external-browser launch plus `requestUrl` exchange path. It records, for Facebook/Instagram, X, and LinkedIn:

- whether installed-app PKCE is supported;
- whether a confidential client secret is required;
- allowed redirect URI forms;
- scopes and account-discovery requirements;
- access-token and refresh-token behavior;
- whether mobile requires a manual-token fallback.

If viable, a provider-neutral helper will start authorization, validate exactly one matching callback, enforce timeout/cancellation, exchange and normalize token data, and store tokens only through the existing per-device `Secrets` wrapper. It never logs authorization codes, state, access tokens, or refresh tokens. Providers supply URLs, scopes, token parsing, and account lookup. A provider that requires a confidential client or hosted redirect uses an explicit manual-token or assisted fallback instead of weakening the security model.

### Platform adapters

The adapters reuse the M5 adapter contract, delivery state machine, persisted send keys, hand-over service, channel validation, approval checks, and secret storage.

- Facebook Pages: OAuth discovery, page selection, text/image publishing, and native scheduling with `scheduled_publish_time`; native scheduling reuses the M5 hand-over lifecycle.
- Instagram Business: Meta OAuth and business-account discovery, required image-hosting strategy, media-container creation, publishing, and explicit refusal of unsupported content. It is not handed over until hosting and scheduling behavior are proven.
- X: OAuth/API publishing, media upload, threads, platform character counting, and an assisted fallback when the account's API tier cannot publish.
- LinkedIn profile: OAuth, profile lookup, and image/text publishing.
- LinkedIn company pages: a separate permission and account-discovery path, enabled only when the required LinkedIn product access is available; assisted mode remains available otherwise.

Every adapter provides connection testing, explicit scope/permission errors, retry-safe unknown-outcome handling, a clear channel method, and contract/provider tests. API-to-assisted fallback is never silent.

### Image generation and crops

OpenAI image generation is one capability shared by the composer and the Claude tool. The user or Claude supplies a prompt; the plugin calls the OpenAI Images API through `requestUrl` using the per-device OpenAI secret; the result is saved in the configured vault attachments folder; and the note receives a normal `media:` entry with focal-point metadata.

The composer window supports prompt, optional negative guidance, aspect-ratio presets, focal-point selection, regeneration, and cancellation. It previews the original and derived crops before approval and never publishes implicitly. Crops are derived from the original and focal point, preserving the source asset so they can be regenerated.

### Token health

Token health is provider-neutral. The plugin records expiry or last-verified information only when the provider exposes it, never infers expiry from a failed post alone, and shows “needs attention” when a connection test or refresh fails. Secrets and refresh tokens remain device-local. Providers that do not expose expiry are not presented as having a precise health countdown.

### Documentation and release

Each provider gets a setup guide covering app registration, scopes, account discovery, API-tier limitations, testing, and assisted fallback. The community-plugin submission follows the adapter and smoke-checklist gates. The M6 release must include manual smoke runs for each provider and both API and assisted modes where applicable.

## Data and security constraints

- No companion server is introduced; the plugin remains self-contained.
- Credentials, OAuth tokens, refresh tokens, and the OpenAI key stay in per-device secret storage and never enter synced settings, notes, logs, or generated release files.
- OAuth callbacks accept only loopback requests with the expected state, one-time code, and short timeout.
- Unknown commit outcomes are never retried automatically unless the provider's operation is demonstrably idempotent.
- Approval and content digests cover every field sent to a provider, including generated media, focal point, crop, and scheduled time.
- Publisher-only scheduling and the M5 10-minute scheduling safety rules remain in force.
- Every platform retains an assisted fallback when API access is unavailable or insufficient.

## Success criteria

- Desktop OAuth completes safely for every provider that supports an installed-app flow; unsupported providers have a documented manual-token or assisted path.
- Facebook Pages can publish and hand over native scheduled posts with startup reconciliation and out-of-sync actions.
- Instagram Business can publish approved image posts with a documented, tested hosting strategy.
- X and LinkedIn adapters publish supported text/media content with safe unknown-outcome behavior and assisted fallback.
- Generated images are stored in the vault, represented in note frontmatter, previewable, and crop-able by focal point.
- Token-health notices are accurate and never expose secrets or claim unsupported precision.
- Full automated gates pass, the M6 smoke checklist passes on test accounts, and the branch is reviewed before merge.
