# M6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Add secure desktop OAuth where supported, Facebook/Instagram/X/LinkedIn API adapters with assisted fallbacks, OpenAI image generation and focal-point crops, token-health reminders, and release documentation without weakening M5 safety guarantees.

**Architecture:** Build provider-independent OAuth and credential-health services around the existing `Secrets`, `PlatformAdapter`, `AdapterRegistry`, and channel settings boundaries. Add each platform as an isolated adapter with its own API client, account discovery, validation, contract cases, and assisted fallback. Keep image generation and crops as vault-local services consumed by both the composer and MCP.

**Tech Stack:** TypeScript, Svelte 5, Zod, Obsidian `requestUrl`, Obsidian per-device secret storage, esbuild, Vitest, existing M5 adapter contract and hand-over service.

**Spec:** `docs/superpowers/specs/2026-10-01-m6-design.md`

## Global Constraints

- No hosted companion server; the plugin remains self-contained.
- Credentials, OAuth tokens, refresh tokens, and the OpenAI key stay in per-device secret storage and never enter synced settings, notes, logs, or release files.
- OAuth callbacks accept only loopback requests with expected state, one-time code, and a short timeout.
- Unknown commit outcomes are never retried automatically unless the provider operation is demonstrably idempotent.
- Approval and content digests cover every field sent to a provider, including generated media, focal point, crop, and scheduled time.
- Publisher-only scheduling and M5 scheduling safety rules remain in force.
- Every platform retains an explicit assisted fallback when API access is unavailable or insufficient.
- Obsidian 1.11.4+ and Node 22+ remain the minimums.

## Review Focus

- A callback from a different origin, wrong state, reused code, or late callback must never exchange a token; pin in `test/auth/oauth.test.ts`.
- A provider returning a successful HTTP status with malformed JSON, a revoked refresh token, or an ambiguous publish response must fail closed; pin in each adapter test.
- Meta media URLs must be reachable by the provider but must not expose vault paths or credentials; pin in `test/platforms/instagram/media.test.ts`.
- A generated image or crop edited after approval must change the approval/content digest; pin in `test/publish/sync.test.ts` and image tests.
- Missing provider scopes, API-tier restrictions, and unsupported account types must produce a visible connection error and preserve assisted mode; pin in each settings/adapter test.
