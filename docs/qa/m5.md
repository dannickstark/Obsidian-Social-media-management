# M5 manual QA — auto-publish adapters wave 1

Setup: `npm run seed && npm run dev`, open `dev-vault/` in Obsidian 1.11.4+ on a desktop.

## Link cards (#93)
- [ ] **(QA)** Known limit — redirects: `LinkCardFetcher` (`src/platforms/og.ts`) refuses to *request* a private, loopback or link-local host (127.0.0.1, 10.x/172.16-31.x/192.168.x, 169.254.x incl. cloud metadata, IPv6 loopback/unique-local/link-local/IPv4-mapped, `localhost`, `.local`), but `requestUrl` follows redirects itself and never exposes the final URL to this class, so a public link that redirects to one of those addresses is not caught. Accepted as a known limit: the request the fetcher makes is always a plain `GET` with no credential attached (no cookie, no `Authorization`, nothing from `app.secretStorage`), and the response is only ever parsed as text for the OpenGraph tags — never executed, never written anywhere but the in-memory per-session cache. The exposure from a malicious redirect is bounded to "an unauthenticated GET happened against an internal address", not a credential leak or a write. To exercise this by hand: put a URL that 302s to `http://169.254.169.254/` behind a public shortener, paste it into a post's body, and confirm in the network tab (or a proxy) that a request goes out to the redirect target — a full fix would need control over the redirect chain, which `requestUrl` doesn't offer.
- [ ] Paste a link to a normal public article into a post body; its preview card picks up the title, description and image within a second or two, and a second post with the same link shows the cached card instantly.
- [ ] Paste `https://127.0.0.1/`, `https://localhost/`, `http://example.com/` (plain http) and a link to a `.local` address: none of them ever shows a fetched card (no title/description/image beyond the plain domain/URL row), and no request for them appears in a network trace.
- [ ] Type a URL into the composer one character at a time: only one fetch happens, after typing settles for under a second — not one fetch per keystroke.
