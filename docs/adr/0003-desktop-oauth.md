# ADR 0003: Desktop OAuth feasibility

Status: Feasibility finding; provider authorization remains unverified
Date: 2026-10-01

## Context and probe

M6 needs a self-contained Obsidian plugin. A desktop authorization flow therefore needs a public-client grant with PKCE and a browser redirect to a short-lived local listener; an app secret cannot be protected in distributed plugin code. The throwaway `scripts/oauth-probe.mjs` starts an HTTP listener bound to `127.0.0.1` on an ephemeral port and accepts one `GET /callback` with one nonempty code and the expected state. It rejects a foreign Host header, a mismatched state, and late callbacks, then closes. Its `--self-test` sends a synthetic callback to itself and generates an S256 PKCE challenge. It does not open a browser, call a provider, exchange a token, store a credential, or log code/state/verifier values.

On 2026-10-01, `node scripts/oauth-probe.mjs --self-test` accepted a synthetic callback at `http://127.0.0.1:57157/callback`. The port is allocated anew on each run. This proves the local transport and rejection behavior only; it cannot establish that any provider will accept that redirect URI or grant the requested scopes.

## Decision

Keep the M6 provider-neutral login helper conditional on a credential-free, provider-approved flow. LinkedIn's documented native flow is a candidate after app enablement. X is a candidate after callback registration and scope checks. Meta remains a discovery blocker for desktop automatic connection. No provider should be marked connected solely because the local listener works. Keep each platform's assisted path available, and require a provider-specific test app before building a token exchange or promising account discovery.

The next validation pass should register test apps, try the exact redirect URI including path and port, request the listed scopes, perform a PKCE exchange where supported, and record token lifetimes without retaining credentials in notes or repository files. Production OAuth code is outside this ADR and probe.

The shared desktop helper added after this feasibility spike accepts a validated callback path, so `/redirect` can be used for a provider that requires it. Its token POST uses Node's direct HTTPS request and rejects every 3xx response without following `Location`. Obsidian `requestUrl` was not used for this exchange because its redirect-following behavior cannot be disabled reliably; a 307/308 could forward the authorization code and PKCE verifier to a different host. This transport decision does not change the unverified provider outcomes above.
